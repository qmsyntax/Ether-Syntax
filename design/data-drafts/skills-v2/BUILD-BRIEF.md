## Build

1. **The generator reads v2.**
   - Point `tools/skills/emit_abilities.py` (and `skill_tables.py`) at `design/data-drafts/skills-v2/`.
   - It writes abilities, statuses, affinities, skill trees and scrolls for all 18 affinities.
   - Dropped skills leave the game. Existing ids keep their ids. Each ability keeps `base_rune` and `signature`, plus its `ascension` field map (the ascension boost code reads aspects through the rune stat groups; make sure every skill's aspects reach a real number).
   - Each draft's extra fields (`serves`/`role_fit`, `starter_slot`, `parent_trait`, `change_note`) may be carried or dropped; choose and say which.
2. **Fix the draft clashes in the drafts, then re-run:**
   - Skill id `fever_break` is defined by both Life and Disease: rename one.
   - Anchor conflicts the exporter reported: `quarry_throw` (EAR-4a vs EAR-6b), `heartwood` (NAT-1a vs NAT-2a), `sting_dart` (POI-1a vs POI-4a). Make each skill sit on exactly the rune its v2 draft names.
   - Set Solid (Ice) cannot form a closed full ring with the runes a new character starts with (`tests/full_ring_check.tscn`). Make `full_ring_check` pass for every start of every affinity (single-affinity starts, as it checks now) without weakening the check. Prefer changing which runes a start knows (rune_discovery's "start" lists, generated by `tools/runes/rune_sources.py`) over changing rune chemistry, and report what you changed.
3. **The statuses:** add the 14 missing statuses, and every status the v2 drafts define in `new_mechanics`, to the status engine as data (generic keys; `statuses.json` is generated). Each one needs a `desc` and must pass StatusText's worded-key check.
4. **The role mechanics.** Build every v2 `new_mechanics` entry generically, in the existing data-driven style, reusing what exists. Several designers already share keys; keep one implementation per idea:
   - one ward pool (Holy, Water's Crush ward, Ice Shell, Unholy's Black Shroud), with one cap;
   - one weapon coat / `strike_payload` (Fire, Poison);
   - one taunt (`taunted`; Earth, Metal, Unholy's leash may reuse it), one aura, one drain (`drain_frac`) and one buff that reaches summons. Merge Death's `thrall_` buffs with the shared-buff radius;
   - counters and parries (Wind, Metal, Holy); `conjure_weapon` (Blood); stealth / vanish / ambush (Dark); the stolen-life store (Unholy); Edge Heat (Metal); quicken on Overload (Lightning); Infected spreading by touch (Disease); thrall cap, command and swap (Death); growth-patch summons (Nature); Lit and sear (Light); twilight (Dream); stasis and ice walls (Ice).
   - Where something is too big to build properly now, it must still be castable: give it the nearest existing behaviour, set `"simplified": "what is missing"`, and list it. Aim for few simplifications; these are the roles.
5. **Holy and Unholy:**
   - a colour each;
   - their kit (three starters);
   - their reflux tier, rule and rule mechanics;
   - their skill tree;
   - a test character each;
   - rune glyphs that draw in-game. They use Old Turkic code points (U+10C00-10C21), drawn on Windows by Segoe UI Historic. Check the rune board and palette actually show them; if Godot's fallback font cannot draw them, add a font fallback.
6. **Everything that named a dropped skill.** `water_bolt` was the water kit's ranged skill and `prime_default`. Tests, bots, shots, design/14's worked examples (Tidal Bore, Pressure Jet) and seal-drown shots use dropped skills. Move each to a v2 skill that shows the same thing. Do not keep dropped skills alive for tests.
7. **The ascension and the level lock** stay as built (CLAUDE.md "Ascension" and "Rune seals"). Test characters for all 18 affinities: stage 0, 4 stars, every construct, and the bar refilled after a bind.
